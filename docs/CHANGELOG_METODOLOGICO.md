# Changelog Metodológico

- 2026-05-21: Implementação inicial do NutEV Audit Engine para rastrear a cadeia documento → claim → recomendação candidata, reduzindo risco de recomendações não suportadas.
- 2026-07-21: Ampliação das fontes bibliográficas padrão da busca (Artigo 1 — revisão de escopo JBI/PRISMA-ScR). O conector DOAJ (Directory of Open Access Journals), já declarado no `source_priority` das buscas desde 2026-06-27, passou a ser efetivamente executado após a correção do despacho de provedores (o pipeline agora deriva os provedores suportados do registro implementado do orquestrador). Adicionado o conector SciELO ao `source_priority` padrão das buscas (busca1, busca2a, busca2b, artigo3_framework), recuperando literatura ibero-americana/brasileira sistematicamente sub-representada nos indexadores internacionais — reforço metodológico relevante para uma tese do PPGNH/UnB. Ambos operam por padrão em modo de página única (reprodutível); a recuperação ampliada continua sendo opt-in por variável de ambiente (`NUTEV_DOAJ_MAX_RESULTS` / `NUTEV_SCIELO_MAX_RESULTS`). A cobertura do SciELO é escopada ao prefixo DOI 10.1590 via API estável do Crossref (documentado em `docs/SEARCH_PROVIDERS.md`).
- 2026-07-22: Backend de OCR opcional (olmOCR). Além do Tesseract (padrão, determinístico, offline, cache content-addressed), o pipeline de extração passou a aceitar um backend por VLM — olmOCR (allenai/olmocr) — ativável por `NUTEV_OCR_BACKEND=olmocr`. Ele gera Markdown de PDFs com tabelas/equações/layout complexo, mas é **não-determinístico** e **GPU-bound**, portanto é estritamente opt-in e **sempre com fallback automático para o Tesseract** quando indisponível ou em erro. O NutEV **não distribui pesos de modelo**: o usuário instala o `olmocr` e é responsável por revisar a licença dos pesos. A saída do olmOCR é tratada como **extração assistiva** (revisão humana continua governando) e a não-determinística é registrada aqui; trocar de backend invalida o cache de OCR automaticamente. O padrão do sistema permanece o Tesseract, então execuções padrão não mudam.
- 2026-07-21: Reconciliação do `source_priority` declarado com os provedores executáveis. Removidas duas entradas fantasma que constavam na configuração das buscas mas não possuíam conector implementado e eram silenciosamente ignoradas em toda execução: `google_cse` foi renomeado para o identificador real `google_pse` (Google Programmable Search, opcional; só executa com chaves configuradas — sem chaves, autoexclui-se, portanto execuções sem credenciais permanecem idênticas) e `ddg_web` (DuckDuckGo, sem conector; scraping fora de escopo) foi removido. Nenhuma das entradas jamais foi executada, logo o comportamento efetivo das buscas sem credenciais não muda; a configuração passa a refletir com honestidade o que de fato roda.

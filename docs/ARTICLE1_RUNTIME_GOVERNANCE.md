# Article 1 runtime governance boundaries

The NutEV Evidence Engine is the single operational execution layer for Article 1. This runtime implementation must not be interpreted as completion of scientific gates.

## Authority

1. Protocol/codebook + D-xxx decisions define the intended scientific method.
2. The exact Git SHA defines what the software actually executed.
3. Human reviewers retain authority for inclusion, ABCD coding, relations and adjudication.
4. Google Sheets is a synchronized audit/export surface, not a competing execution engine.

## Generated is not executed

The existence of a search string, codebook, database table, UI control, export path or test does not establish that a scientific action occurred.

## Calibration is not PRISMA

STAGING and CALIBRATION records remain outside formal PRISMA accounting. Formal PRISMA requires the frozen authorized lineage and completed formal screening.

## ABCD is not a quality score

Presence/depth are component-specific descriptive variables. The runtime does not calculate a global ABCD score, mean depth, maturity score, document ranking or evidence-quality interpretation from ABCD.

## Relations are explicit only

Co-occurrence is derived separately. It cannot be promoted to a relation without explicit source evidence. The runtime must not infer causal direction or behavioral function.

## Article 1 appraisal

Generic Evidence Matrix quality instruments remain reusable for other workflows but are not automatically mandatory for Article 1. Methodological characterization is descriptive and separate from ABCD.
